# CalcPilot — פרויקט מוכן לעבודה ב־VS Code

## הפעלה מהירה

1. התקינו Node.js LTS גרסה 22 ומעלה.
2. חלצו את ZIP ופתחו את תיקיית calcpilot ב־VS Code.
3. ב־Windows: הפעילו START-WINDOWS.bat. ההפעלה הראשונה מתקינה את התלויות אוטומטית.
4. לחלופין, בטרמינל מתוך התיקייה:

```
npm install --no-package-lock
npm run dev
```

פתחו http://localhost:3000 (או בפורט שהטרמינל מציג). אין צורך במפתח AI או בסיס נתונים. המרת מטבעות בשער ייחוס דורשת אינטרנט לשירות Frankfurter; שער ידני עובד ללא שירות חיצוני.

## מה עובד

- אתר Next.js / React עם עמודים נפרדים, עיצוב רספונסיבי, ניווט וחיפוש מחשבונים.
- 16 מחשבונים: מחשבון רגיל, מחשבון פיננסי, תמהיל משכנתא, משכנתא לפי הכנסה, משכנתא + הלוואה משלימה, מחזור, הלוואה אישית, יחס החזר, חיסכון, יעד חיסכון, קרן חירום, דלק / טעינה, אחזקת רכב, מימון רכב, מס רכישה ומס שבח, והמרת מטבעות.
- חישוב מיידי, סליידרים, השוואה לתרחיש שמור, הדפסה / שמירה כ־PDF דרך הדפדפן.
- לוח סילוקין מלא והורדת CSV.
- גרפים אינטראקטיביים לתכנון פיננסי: בחירת נקודה בעכבר / מגע / סליידר, הסתרת סדרות, וטבלת נתוני גרף נגישה.
- ניהול תקציב בית: הכנסות, הוצאות, קטגוריות, חודשים, תקציב, שיעור חיסכון והשוואת חודש קודם.
- ניהול רכב: מספר רכבים, הוצאות לפי רכב וחודש וסיכום שנתי.
- גיבוי JSON ושחזור לכל דשבורד, יצוא CSV, מחיקת רישום וחיפוש בטבלה בלי לשנות סיכומי חודש.
- ממשק, תיאורי מחשבונים, הנחות חישוב, מדריכים ודפי מידע בעברית / RTL, באנגלית וברוסית. השפה נשמרת במכשיר.
- USD, ILS, EUR, GBP, CAD, AUD כתצוגת מטבע בלבד, ללא המרת שער.
- המרת 12 מטבעות עם שער ייחוס ותאריך פרסום, שער ידני, החלפת צמד ועמלה יחסית וקבועה. שערי ייחוס אינם הצעת עסקה בנקאית.
- מס רכישה מדורג לדירת מגורים יחידה או נוספת וחלקי בעלות, ואומדן מס שבח עם בסיס מוצמד, הוצאות ופחת. החישובים בשקלים בלבד ואינם שומה.
- חמישה מדריכים, כל אחד מעל 500 מילים בכל שפה, עם דוגמאות וטיפים, תוכן עניינים, זמן קריאה וקישורים למחשבונים. אודות, פרטיות, תנאים, יצירת קשר, sitemap.xml ו־robots.txt.
- בדיקות מנוע פיננסי ותהליך GitHub Pages אוטומטי.

## מה צריך לשנות לפני העלאה ציבורית

העתיקו .env.example לשם .env.local ומלאו:

```
NEXT_PUBLIC_SITE_URL=https://your-domain.com
NEXT_PUBLIC_CONTACT_EMAIL=your@email.com
```

הדומיין חייב להיות הכתובת האמיתית, ללא לוכסן בסוף. פרטי קשר מופיעים בעמוד Contact. יש להשלים את זהות המפעיל ותנאי הפרטיות בהתאם לפעילות האמיתית. אין טופס ששולח דוא״ל: הקישור פותח את אפליקציית המייל.

שם ומיתוג: רכיב src/components/Shell.jsx; צבעים ועיצוב: src/app/globals.css; חישובים: src/lib/finance.mjs; רשימת כלים ומדריכים: src/lib/catalog.mjs.

## בניית גרסת הפצה

```
npm test
npm run build
```

הקבצים המוכנים להעלאה יופיעו ב־out. תיקיית prebuilt-site המצורפת היא גרסה קודמת ואינה כוללת בהכרח את העדכונים האחרונים. השתמשו בבנייה החדשה מתוך out. לפני שימוש ציבורי בנו מחדש עם הדומיין והאימייל שלכם, כדי לעדכן sitemap ועמוד Contact.

## פריסה ב־Vercel

העלו את תיקיית הפרויקט למאגר GitHub וחברו לפרויקט Vercel. הגדירו את שני משתני הסביבה לעיל. פקודת הבנייה היא npm run build, תיקיית התוצאה out. הוסיפו את הדומיין שלכם במסך Domains.

## פריסה ב־GitHub Pages

במאגר GitHub: Settings → Pages → Source: GitHub Actions. התהליך המצורף ירוץ בכל push ל־main. הוסיפו Repository Variables: SITE_URL, CONTACT_EMAIL. לדומיין פרטי או מאגר user.github.io השאירו BASE_PATH ריק. אם האתר בנתיב /repository, הגדירו BASE_PATH=/repository. קובץ CNAME יידרש עבור דומיין פרטי; הוסיפו אותו לתיקיית public לפני build. הגדירו DNS לפי ההוראות שמציג GitHub.

## שמירת נתונים וחשבונות

המערכת עובדת ללא הרשמה: הנתונים נשמרים רק בדפדפן הנוכחי. אין שרת, כניסה עם Google, סנכרון, חיבור בנק או שחזור ענן. אין לשלוח גיבויי נתונים פרטיים למאגר GitHub. ניקוי נתוני הדפדפן מוחק רישומים. גיבוי ושחזור מאפשרים העברה ידנית בין מכשירים. שינוי מטבע אינו ממיר נתונים — בחרו מטבע אחד לכל התקציב.

## חישובים והנחות

מס רכישה: מדרגות דירה יחידה נבדקו מול סימולטור רשות המסים, לתקופה 16.1.2025–15.1.2028; דירה נוספת לפי כל־זכות עד 31.12.2026. תאריכים מחוץ לטווח אינם מחושבים. הסיווג והקלות מיוחדות אינם נבדקים אוטומטית. חלק דירה מחושב לפי שווי הדירה השלמה ואז מוכפל בחלק הנרכש.

מס שבח: אומדן 25% משבח ריאלי חיובי. יש להזין הוצאות שכבר הוצמדו בנפרד למועד המכירה. חישוב ליניארי מוטב הוא אפשרות רק לאחר בדיקת זכאות עצמאית. לא כלולים פטורים, מס יסף, שיעורים היסטוריים, קיזוז הפסדים, פריסה, זכויות בנייה או פחת מורכב. יש לאמת עם איש מקצוע ועם השומה הרשמית.

המרה: Frankfurter API v2 מספק טבלת שערי ייחוס ותאריכי פרסום; אין הבטחה לזמינות או להצעת בנק. הבקשה כוללת בסיס USD ורשימת מטבעות בלבד, ולא סכומים. כישלון אינו מוחלף בשער מדומה; שער שמור מסומן בהתאם. עמלה קבועה נקובה במטבע היעד והעמלה היחסית מחושבת לפני עמלות. בחירת המטבע במעטפת האתר עדיין משנה תצוגה בלבד.

מחשבון התמהיל תומך בריבית קבועה, פריים, משתנה וצמודי מדד עם תחזיות לפי שנים. שאר מחשבוני ההלוואות מחשבים ריבית קבועה, ללא הצמדה, מסים, ביטוח או עמלות אלא כאשר יש שדה מפורש. כושר החזר לפי יחס לבחירת המשתמש, פחות התחייבויות והלוואה משלימה. המימון מוגבל גם על ידי ההון העצמי. אין קביעה שהבנק יאשר את ההלוואה או את מקור ההון העצמי. כללי מדינות אינם מוזנים מראש.

בעלות רכב: צירוף החזר מימון מלא לירידת ערך יכול לספור קרן פעמיים; לשם עלות כלכלית יש להזין רק את רכיב הריבית, כמוסבר במחשבון. חיסכון מניח תשואה קבועה ולא מובטחת.

## פרסומות והכנסות

נוספה תשתית למודעות אוטומטיות של Google AdSense, כבויה כברירת מחדל. לא הוגדר מזהה מפרסם ולא מוצגות מודעות אמיתיות. אין חלון מודעה מקומי, ספירה לאחור או חסימת תוכן. Google קובעת אם ומתי להציג מודעות מעבר, את התדירות ואת אפשרויות הסגירה; אין הבטחה למודעה בכל פתיחה או למשך 5 שניות. אין הבטחת הכנסה.

### לפני הפעלה

1. פרסמו את האתר בדומיין ציבורי עם HTTPS והגדירו את `NEXT_PUBLIC_SITE_URL` לכתובת המדויקת.
2. פתחו חשבון AdSense, הוסיפו את האתר ובצעו אימות ואישור לפי ההנחיות בחשבון. אפשר להשתמש בשיטת אימות נתמכת שאינה דורשת טעינת מודעות, כגון קובץ `ads.txt`; הוסיפו אותו לתיקיית `public` עם השורה המדויקת שנמסרה בחשבון. אין להשתמש במזהה דמה.
3. ב־AdSense הפעילו מודעות אוטומטיות, ובמידת הרצון מודעות מעבר במסך מלא. בדקו את התצוגה המקדימה והרחיקו מודעות מכפתורי מחשבונים ושדות כדי למנוע לחיצות מקריות.
4. שלבו מערכת הסכמה מוסמכת של Google בהתאם למדינות הקהל ולדין החל. התשתית הנוכחית דורשת ממשק TCF תקין (`window.__tcfapi`), וחוסמת פרסום אם המערכת חסרה או טרם השיבה. אין כאן מערכת הסכמה פעילה, וחיבור שלה הוא שלב נפרד לפני הפעלת הפרסום.
5. השלימו זהות מפעיל, פרטי קשר ומדיניות פרטיות שמתארת את Google, העוגיות, ספק מערכת ההסכמה וזכויות המשתמשים. בדקו דרישות נוספות במדינות אחרות; דיווח TCF שאין תחולת GDPR אינו תחליף לחובות פרטיות אחרות.
6. רק לאחר השלמת השלבים, הגדירו בסביבת הבנייה:

```dotenv
NEXT_PUBLIC_ADSENSE_ENABLED=true
NEXT_PUBLIC_ADSENSE_CLIENT_ID=
```

מלאו את המשתנה השני במזהה הציבורי האמיתי מהחשבון, בצורת `ca-pub-` ואחריו 16 ספרות. זה אינו סיסמה. בנו מחדש עם `npm run build` ופרסמו את תיקיית `out`. שינוי משתני `NEXT_PUBLIC_` מחייב בנייה חדשה. להשבתה הגדירו `NEXT_PUBLIC_ADSENSE_ENABLED=false`, בנו ופרסמו מחדש.

### חיבור מערכת ההסכמה

יש לטעון את התג הרשמי של מערכת ההסכמה לפני רכיב הפרסום בהתאם לתיעוד הספק. אם ממשק TCF מתווסף מאוחר יותר, חיבור הספק צריך לשלוח את האירוע הבא כשהממשק מוכן:

```javascript
window.dispatchEvent(new Event('calcpilot:cmp-ready'));
```

האירוע רק מפעיל בדיקה מול המערכת, ואינו נותן הסכמה. התשתית מאזינה לשינויים דרך `addEventListener` של TCF. כאשר GDPR חל, היא מאפשרת רק הסכמות מפורשות לספק Google ולמטרות הנתמכות, וחוסמת הגבלות מפרסם. זו בחירה שמרנית: סירוב, נתונים חסרים או מסלול שמבוסס רק על אינטרס לגיטימי לא טוענים מודעות. מערכת ההסכמה חייבת לאפשר שינוי וביטול הסכמה, ולנהל גם סקריפטים שכבר נטענו; הסרת רכיב React אינה מסירה סקריפט שכבר בוצע. יש לבדוק את התנהגות הביטול עם הספק לפני השקה.

### מתי המודעות נטענות

- בפתיחת הדף הראשונה לאחר הפעלת הפרסום נשמר רק סימון ביקור קודם (`cp-ad-previous-visit`), ולא נטען סקריפט AdSense. מעבר בין מסכים באותה פתיחה אינו נחשב פתיחה נוספת.
- בטעינת דף הבאה, כולל רענון, הרכיב יכול לטעון AdSense לאחר אישור ההסכמה. הסימון מתייחס לכניסה קודמת, ולא מוכיח שהמשתמש השלים חישוב.
- אם האחסון המקומי חסום, הרכיב אינו טוען מודעות. מחיקת אחסון האתר מאפסת את סימון הביקור.
- אין טעינת פרסום בכתובת המקומית או בדומיין שאינו תואם לכתובת האתר שהוגדרה.
- כשהפרסום כבוי, הרכיב אינו טוען סקריפט ואינו שומר סימון ביקור.

יש לבדוק על האתר המאושר בפועל את פריסת המודעות, פרטיות והסכמה. אין ללחוץ על מודעות עצמיות או ליצור תנועה מלאכותית. ראו גם LAUNCH-PLAN-HE.md.

## אימות

הריצו `npm test` ו־`npm run build` לפני פרסום. בדיקות דפדפן בפיתוח אינן אישור נגישות ואינן מחליפות בדיקות במכשירי iPhone ו־Android אמיתיים. לפני השקה בדקו מילוי מחשבונים, שמירה לאחר רענון, עריכה וביטול מחיקה, שיתוף, גיבוי ושחזור, שימוש ללא רשת והדפסה.

## שיפורי שימוש והשקה

- נתוני מחשבונים תקינים נשמרים אוטומטית במכשיר. ניתן לשמור עד 8 תרחישים בעלי שם לכל מחשבון, לטעון, לשנות שם, למחוק ולהשוות תוצאות. השוואות הוותיקות נשמרו.
- אזור התרחישים מתקפל. שיתוף קישור כולל רק שדות שנבחרו במפורש; הנתונים בחלק שאחרי #, גלויים לכל בעל קישור ואינם מוצפנים. הנמען צריך לאשר טעינה. תוצאות שמורות משקפות את השער וההנחות בעת השמירה, לא נתונים חיים.
- תקציב ורכב: עריכת רשומה, ביטול המחיקה האחרונה במהלך פתיחת המסך, גיבוי JSON מתוארך ותזכורת שבועית. תאריך הגיבוי מציין בקשת הורדה ולא הוכחה שהקובץ נשמר.
- פירוש תוצאות ממוקד לכל כלי, סימון מיקוד ברור, ניווט מקלדת בתפריט הנייד ודף הצהרת נגישות. לא בוצע אישור מקצועי לעמידה בתקן.
- גרסת הפצה כוללת manifest, אייקונים ומטמון לא־מקוון לכל העמודים והקבצים המקומיים. נדרש HTTPS או localhost וטעינה ראשונית מוצלחת. התקנה מוצעת בדפדפנים תומכים; ב־iPhone: שיתוף ב־Safari ואז הוספה למסך הבית. עדכון גרסה מוצג כאשר service worker חדש מוכן. אין הבטחת שער טרי ללא רשת. שרת הפיתוח אינו מפעיל מטמון זה.

## שלושה עדכוני מטבע ביום

חלונות הבדיקה הם 00:00, 08:00 ו־16:00 UTC; שעות מקומיות משתנות לפי אזור זמן ושעון קיץ. טבלת USD אחת מספקת המרות צולבות לכל 12 המטבעות. מעבר בין צמדים אינו מבקש שער מחדש. רענון ידני יכול ליצור בקשה נוספת. אם חלון הוחמץ כשהדפדפן סגור, הבדיקה מתבצעת בפתיחה הבאה; כישלון מציג שער שמור עם אזהרה, או שאין חישוב ללא שער. אזהרה נוספת מוצגת כאשר תאריך פרסום השער בן יותר מארבעה ימים.

לעדכון גם כשהאתר סגור נוסף `schedule` לתהליך GitHub Pages בשלוש השעות הללו. יש להעלות את המאגר, להפעיל GitHub Actions ו־Pages ולהגדיר את משתני הפריסה. התהליך שולף `public/exchange-rates.json`, בודק ובונה מחדש ואז פורס. זמנים מתוזמנים ב־GitHub עשויים להתעכב, ותהליך שנכשל אינו פורס שערים פגומים. התזמון אינו פעיל על מחשב מקומי ולא הוכח בפריסה ציבורית. בשירות אירוח אחר יש להגדיר job מקביל להרצת `node scripts/fetch-rates.mjs` ואז בנייה ופריסה. ספק השערים מפרסם בעיקר בימי עסקים; שלוש שליפות אינן מבטיחות שלושה שינויי שער.

בשימוש ב־BASE_PATH יש להגדיר גם `NEXT_PUBLIC_BASE_PATH` לאותו ערך; התהליך המצורף עושה זאת אוטומטית. מידע פרטי וגיבויים אינם נכללים בקובץ השערים הציבורי.

## שערי אישור חיצוניים

יש להשלים זהות מפעיל, דומיין ואימייל אמיתיים, ביקורת מקצועית של כללי מס והצהרות משפטיות, בדיקת נגישות מקצועית ובדיקת מובייל פיזית. AdSense נשאר כבוי עד אישור האתר, מזהה אמיתי ומערכת הסכמה מתאימה. השיפורים הטכניים אינם אישור מס, אישור פרסום או אישור נגישות.

## תפריט נגישות — 12.10.2026

כפתור צף בצד שמאל פותח תפריט בעברית, באנגלית או ברוסית. אפשר להגדיל טקסט עד 180%, לבחור גופן וגובה שורות, להשתמש בארבע ערכות צבע, בגווני אפור, בסימון קישורים וכותרות, במיקוד מוגבר, בסמן גדול, בהפחתת תנועה, בהסתרת איורים דקורטיביים ובקו או מסכת קריאה. הגדרות נשמרות במכשיר וניתנות לאיפוס; גרפים ונתונים אינם מוסתרים. ניתן להמשיך להשתמש גם בהגדלה המובנית של הדפדפן.

הקראה לפי בקשה כוללת טקסט גלוי בעמוד או טקסט שסומן לפני פתיחת התפריט, בחירת קול ומהירות, השהיה, המשך ועצירה. היא משתמשת ב־Web Speech API; תמיכה בעברית וקולות זמינים תלויים בדפדפן ובמערכת ההפעלה. קולות מסוימים עשויים להשתמש בשירות מקוון. אין הפעלה אוטומטית ואין שמירת הטקסט בכלי הנגישות. עד 25,000 תווים בכל בקשה. הכלי אינו קורא מסך ואינו אישור עמידה בתקן. ההצהרה המעודכנת נמצאת בעמוד /accessibility/.


## חדש בגרסה 2 — תמהיל, תחזיות ומחשבונים נוספים

עמוד Mortgage הוחלף במחשבון תמהיל מתקדם. ניתן להוסיף עד 10 מסלולים: קל״צ, ק״צ, משתנה צמודה, משתנה לא צמודה ופריים. לכל מסלול סכום ותקופה נפרדים, ריבית התחלתית או מרווח פריים, ותדירות תחנת שינוי במסלולים המשתנים.

תחזיות: עריכת אינפלציה שנתית, שינוי ריבית משתנה בנקודות אחוז ותחזית פריים לפי תקופות. הנתונים הראשוניים הם דוגמאות בלבד; אין חיבור לנתוני בנקים או תחזית רשמית. התחזית האחרונה נמשכת עד סוף התקופה. קיימות דוגמאות ליציבות, עלייה וירידה. קל״צ וק״צ אינם משנים ריבית; במסלולים צמודים הקרן והתשלום מתעדכנים לפי המדד.

תוצאות: החזר ראשון, החזר מרבי, סך החזר, ריבית והצמדה בנפרד, עלות החזר לכל שקל, השוואה לפי מסלול, לוח סילוקין משולב, ושמירת תרחיש להשוואה. עלות לכל שקל = סך החזרים חזויים / קרן מקורית. גרפים: תשלומים חודשיים, יתרת קרן, החזרים מצטברים, פירוק קרן/ריבית/הצמדה ותחזיות ריבית ואינפלציה.

הנחות מדד: גורם חודשי הוא (1 + אינפלציה שנתית)^(1/12). ההצמדה חלה גם בחודש הראשון. אין התאמה למדד ידוע/בסיס, פיגור פרסום, רצפת מדד חוזית או חישוב יומי. ההדמיה אינה בדיקת אישור אשראי או תמהיל רגולטורי.

מחשבון רגיל: פעולות חשבון, אחוזים כחלוקה ב־100, חזקות, שורש, זיכרון והיסטוריה שנשמרת בדפדפן. אין שימוש ב־eval. גרף מציג את סדרת תוצאות ההיסטוריה, לא תחזית כספית.

מחשבון פיננסי: ערך נוכחי PV, ערך עתידי FV, הפקדה PMT, פתרון ריבית שנתית נומינלית, הפקדה בתחילת/בסוף תקופה, ותדירות חודשית/רבעונית/שנתית. NPV/IRR לתזרימים שנתיים, עם תזרים ראשון בזמן אפס. IRR יכול להכיל כמה פתרונות; מוצג הפתרון הראשון שנמצא בטווח החיפוש הנתמך.

מחשבון החזר לפי הכנסה וההלוואה המשלימה עדיין משתמשים בריבית קבועה בודדת לצורך הערכת כושר ההחזר. לתכנון מסלולים עם מדד ותחזיות השתמשו במחשבון התמהיל. חלוקת מסלולים אינה מופעלת באופן אוטומטי בשאר המחשבונים.

אם כבר הפעלתם את הגרסה הקודמת: עצרו את שרת הפיתוח, החליפו את קבצי המקור והפעילו שוב. נתוני תקציב הבית והרכב בדפדפן נשמרים אם ממשיכים באותה כתובת ובאותו דפדפן. מומלץ לגבות אותם לפני החלפה.
